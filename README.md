# Город трафика × Трафик Лаб

Telegram Mini App: кинематографичная воронка для перформанс-маркетологов.
Девять состояний, три протокола (видео), допуск через тест и продажа практикума.

Продуктовая правда — [PRODUCT.md](PRODUCT.md). Визуальные решения — [DESIGN.md](DESIGN.md).
Всё, что противоречит этим двум документам, — ошибка.

## Запуск

```bash
npm install
npm run dev          # http://localhost:5173/meat5/
npm run build        # сборка в dist
npm run typecheck
```

База путей — `/meat5/`: приложение живёт в подпапке GitHub Pages, и dev, preview
и build обязаны использовать одну и ту же базу. Разводить их нельзя: preview начнёт
отдавать index.html вместо бандла, экран останется пустым, а проверки при этом пройдут.

## Что где лежит

| Путь | Что это |
|---|---|
| `src/config.ts` | **Ссылки и цены, которые правит заказчик:** видео, ассистенты, демо-сайт, чекаут. Имена полей — как в ТЗ §34 |
| `src/content/copy.ts` | **Весь текст воронки.** Экран не сочиняет формулировку: нет строки здесь — нет её в интерфейсе |
| `src/content/quiz.ts` | 12 ситуаций допуска, по одной на каждую обязательную категорию ТЗ §15 |
| `src/content/offer.ts` | Тексты оффера и практикума |
| `src/router/flow.ts` | Одиннадцать состояний, `resumeStep()` — куда вернуть человека, `canEnter()` — куда его пускать |
| `src/store/progress.ts` | Прогресс, имена ключей как в ТЗ §32; переживает закрытие приложения |
| `src/lib/analytics.ts` | События воронки, имена как в ТЗ §35 |
| `src/lib/attribution.ts` | Источник трафика: `start_param`, `first_touch`/`last_touch`, признак оплаты |
| `src/lib/useVideo.ts` | Плеер: HLS, восстановление позиции, честный подсчёт просмотра |
| `src/lib/telegram.ts` | Мост к Telegram SDK; без Telegram приложение работает как обычная страница |
| `public/world/` | Кадры мира (webp, готовы к отдаче) |

## Подключить материалы

Всё через `src/config.ts`, пересборка не нужна нигде, кроме самого конфига:

```ts
introAudioUrl: 'https://…/intro.mp3',
video1Url: 'https://…/protocol-01.m3u8',
assistant1Url: 'https://…',
resultDemoUrl: 'https://…',
checkoutUrl: 'https://…',
```

Пока `url` пуст, экран честно показывает плейсхолдер и не запирает воронку:
человек проходит дальше, а материал подставится позже. **Как только ссылка на
видео появится, просмотр считается по-настоящему:** завершение засчитывается
только после 85% фактически просмотренных секунд, промотать ползунок в конец
недостаточно.

**Mini App ничего не знает о конкретном кейсе.** Ниша живёт внутри видеофайлов.
Завтра третий протокол про другой проект — меняется ссылка, воронка остаётся прежней.

## Оплата без бэкенда

Бэкенда нет и в MVP не планируется. Поэтому:

- прогресс живёт на устройстве человека и не переезжает на другой телефон;
- чекаут — внешняя ссылка, приложение не притворяется, что оплата прошла;
- о состоявшейся оплате приложение узнаёт от бота: бот присылает ссылку со
  `start_param`, равным `config.paidStartParam` (по умолчанию `paid`), и
  `src/lib/attribution.ts` выставляет `purchased`.

Цена решения честная и её надо понимать: такую ссылку можно переслать другому.

## Метки кампаний

Telegram Mini App **не получает** utm-метки. Он получает единственный
`start_param`: до 64 символов, только `A-Za-z0-9_-`. Поэтому в ссылку кладётся
короткий код `источник-канал-кампания`, например `tg-post-avgust`, а
`src/lib/attribution.ts` раскладывает его в поля `utm_*`. В веб-версии и при
отладке дополнительно читается обычная query-строка.

## Telegram

Бот пока не заведён, поэтому приложение открывается и в обычном браузере.
Когда бот появится: в BotFather → `/newapp`, URL — адрес GitHub Pages.
`src/lib/telegram.ts` уже умеет разворачивать окно, красить шапку, гасить свайп
вниз (он закрывает Mini App и теряет прогресс), давать тактильный отклик и вести
кнопку «Назад».

## Ассеты

```bash
node scripts/assets.mjs     # assets-src → public/world (ресайз + webp)
```

Исходники (кадры заказчика и сгенерированные сцены) в репозиторий не кладутся:
в `public/world` лежат обработанные версии, которыми живёт приложение.

## Режим отладки

Пройти воронку не по порядку и начать заново — прямо на живой ссылке, с телефона.

| Как включить | Где |
|---|---|
| `?debug=1` в адресе (`?debug=0` — выключить) | браузер |
| пять быстрых касаний левого верхнего угла | Telegram, где адрес не набрать |

Появляется кнопка с жуком в правом верхнем углу. Внутри: список девяти экранов с
переходом на любой, переключатели состояния (материалы пройдены, допуск получен,
жизни, покупка) и «Начать заново с первого экрана».

Флаг лежит в localStorage и переживает перезагрузку, поэтому включать каждый раз
не нужно. Панель намеренно серая и моноширинная — её нельзя спутать с интерфейсом
продукта, и на случайном скриншоте сразу видно, что это служебный режим.

## Проверка вёрстки

```bash
npm run build
npx vite preview --port 4173
node scripts/shots.mjs      # скриншоты девяти состояний в .review + поиск дефектов
```

Скрипт ищет то, что глазами не поймать: горизонтальный скролл, элементы за краем
экрана, контент, запертый под кнопкой действия, обрезанный текст. И отдельно —
пустой экран: без этого стража сканер однажды отрапортовал «дефектов нет» по
белой странице, на которой не отрисовалось вообще ничего.

Смотреть скриншоты глазами всё равно обязательно: механическая проверка не судит
о композиции.

```bash
node scripts/contrast.mjs            # читаемость текста поверх фотографий
```

«Плохо читается» — мнение, поэтому здесь считается число. Скрипт берёт рамку
каждого текстового блока, прячет сам текст, снимает чистый фон под ним и считает
контраст по WCAG: 4.5:1 для основного текста, 3:1 для крупного. Текст под
фиксированной кнопкой не меряется — он уезжает из-под неё при прокрутке.

## Проход воронки целиком

```bash
node scripts/walk.mjs
BASE=https://pavlushapavel.github.io/meat5/ node scripts/walk.mjs
```

Нажимает то же, что нажал бы человек: главную кнопку, play внутри видео, вариант
ответа в тесте — и печатает, что видно на каждом шаге. Остальные проверки
подставляют прогресс в localStorage и смотрят состояния по отдельности; так не
видно, проходится ли маршрут на самом деле. Этот скрипт отвечает ровно на
критерий готовности из ТЗ: человек доходит от входящего сообщения до доступа.

По списку шагов сразу видно, не пропал ли мост и не встал ли маршрут.

## Мобильная адаптация и Telegram

```bash
node scripts/devices.mjs     # пять ширин телефонов + эмуляция Telegram
```

Скрипт гоняет все девять экранов на 320 / 360 / 375 / 390 / 430 и отдельно — в
условиях Telegram: видимая высота 640 из 844, шапка 56, домашняя полоса 34.
Ищет горизонтальный скролл, элементы за краем, контент под шапкой клиента,
кнопку действия ниже видимой области и пальцевые цели меньше 44px.

Настоящий `telegram-web-app.js` в эмуляции блокируется: он перезаписывает
`window.Telegram` своим объектом и рапортует размеры браузера, из-за чего
проверка молча превращается в пустую.
